# CC Switch Remote v4.0.5

上游基线：**v4.0.4**（`farion1231/cc-switch`，已发布 tag，提交 `a29a4f38`）。

这一版把 **Remote** 分支的产品线切到上游 4.0 基线上：页面结构、配置逻辑、供应商/路由/工具生命周期都改用上游 v4 的唯一一套实现，Remote 只在其上补「最终目标位置」——同一套 UI 与逻辑，本机与远端各自持有自己的数据。

## 本版重点

### 1. 单一 UI 体系 + 目标上下文

- 侧栏品牌区下方是全局的**管理目标**选择器，页面结构不再分本机/远端两套。
- 选中远端后，供应商、路由器、MCP、提示词、技能、会话、Hermes 记忆、用量、授权中心、环境检查、导入导出、工具生命周期全部按该主机读写；查询缓存按目标分槽，切换目标不会读到上一个连接的数据。
- 同 profile 换了主机或凭据（连接身份变化）时，旧响应的晚到不会回填新连接。

### 2. 工具环境并入「应用」页

- 上游 v4 新增的「应用」页现在跟随管理目标：远端目标的版本检查、安装/升级/卸载、冲突诊断与安装列表都通过 helper 执行（`tools versions` / `tools run` / `tools probe-installations` / `tools installations`，与本地共用同一套 Rust `tool_environment` 逻辑）。
- 远端设置页的环境页签不再重复提供同一批工具入口，只保留 helper 健康/能力面板和一个指向「应用」页的入口；helper 未广告 `tools` 能力时如实说明并隐藏可操作项。
- 本机专属部分在远端目标下隐藏：Claude Desktop 行、Windows WSL shell 覆盖、客户端启动时的更新检查（仍只用于本机侧栏提示）。

### 3. 本机专属能力在远端明确隐藏或说明

托盘、终端启动、桌面深链、模式/聚合面板、ProfileSwitcher、Hermes Web UI、ZIP 选择器、打开目录/复制路径、发现缓存、Pi live 状态、会话正文阅读等本机专属能力，在远端目标下不渲染或明确标注不支持，不用本机状态冒充远端。

### 4. 数据安全语义保持不变

- 备份失败即停；原子写保留旧目标；暂存提交失败保留暂存文件。
- 远端 helper 不接管外部 daemon：helper 自己起服务、自己收尾。
- 本地与远端数据目录隔离：`~/.cc-switch-remote`（开发构建用 `-dev` 后缀），不写上游 CC Switch 的数据目录。

## 合并期间修掉的问题

- `useMcp`：连接身份变化时，reset 触发的重新拉取可能沿用上一轮的 queryFn 闭包，导致同一个 query key 下用旧主机的响应回答新连接；改为从 ref 读最新目标（并同步修掉 `useSkills` 与 Copilot 额度查询的同类写法）。
- Rust 架构守卫：切换失败回滚时读直连指针改走 `mode::current::local_direct_pointer`，与上游一致。
- 数据库迁移用例按当前 schema 版本（20）断言。

## 未支持 / 待办（如实标注）

- 远端会话：列表、删除、复制恢复命令可用；**正文阅读不支持**（上游 v4 的 reader 是流式 Channel 实现，远端暂无等价通道）。
- 远端 Pi live 状态不可读（helper 的 `live-ids` 只覆盖 OpenCode/OpenClaw/Hermes），远端只信本行记录。
- 依赖 helper 能力的功能按能力门控：旧 helper 缺少对应 capability 时隐藏或禁用，并给出升级说明。
